지금까지 이 세션에서 진행한 작업을 정리해서 GitHub(`main`)에 커밋·푸시한다. 이 프로젝트는 여러 PC를 오가며 작업하고, Claude의 세션 메모리는 PC 사이를 넘어오지 않으므로(`CLAUDE.md` 참고), 다음 세션이 참고할 수 있는 건 git에 커밋된 문서뿐이다.

1. `git status`로 커밋 안 된 변경사항을 확인한다. 코드/설정 파일이 안 커밋된 채 남아있으면 안 되니, 있다면 먼저 정리해서 커밋한다 (테스트 통과 확인 후).
2. `docs/STATE.md`를 최신 상태로 갱신한다:
   - "지금 상태" 섹션 — 이번 세션에서 실제로 바뀐 것(새 기능, 수정된 버그, 새로 알게 된 함정 등)을 반영
   - "다음에 할 일" 섹션 — 아직 안 끝난 것, 사람이 해야 할 수동 작업
   - "진행 중이던 작업" 섹션 — 세션이 끊긴 시점에 뭘 하던 중이었는지 (없으면 "없다"고 명시)
   - **검증 상태**의 테스트 개수는 절대 추측하지 말고 `python -m pytest -q`로 직접 재서 반영 (ffmpeg가 PATH에 없으면 먼저 잡고 돌릴 것)
3. `todo.md`를 갱신한다 — 이번 세션에서 완료한 항목은 `[x]`로 체크하고 **무엇을 어떻게 검증했는지**까지 남긴다. 새로 발견된 할 일이 있으면 적절한 섹션에 추가한다.
4. 커밋 메시지는 한국어로, 왜 이 갱신이 필요한지 남긴다 (`CLAUDE.md`의 커밋 컨벤션을 따름).
5. `git push`로 원격에 반영한다. 만약 원격에 로컬에 없는 커밋이 있으면(다른 PC에서 먼저 푸시한 경우) `git pull --rebase --autostash` 후 다시 push — 이 프로젝트의 GitHub Actions 워크플로도 같은 패턴을 쓴다.
6. 완료 후 사용자에게 뭘 커밋했는지 3줄 이내로 요약해서 알린다.

절대 하지 말 것: 인수인계 문서를 갱신하지 않은 채 그냥 커밋만 하고 끝내는 것. 이 커맨드의 핵심은 "다음 세션이 이 문서만 읽고 바로 이어서 작업할 수 있는가"이다.
